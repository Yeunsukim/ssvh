# SSV 병원 전산 실습 — 데이터 연결·지속성 규칙

이 프로그램의 모든 자료는 병원 DB에 그대로 옮길 수 있게 **표(테이블) + 열쇠(FK)** 구조로 되어 있습니다.
새 화면을 만들거나 고칠 때는 아래 규칙을 반드시 지킵니다.

## 1. 자료 규칙표가 기준이다
- 자료 규칙표는 `js/core/integrity.js`의 `SCHEMA`에 있습니다.
- 자료 묶음 27개(patients, encounters, orders …)는 각각 DB 테이블 1개와 같습니다.
- 새 자료 묶음이나 다른 자료를 가리키는 새 칸(열쇠)을 만들면 **먼저 SCHEMA에 적습니다.**
  - 적을 것: 표 이름, 필수 칸, 열쇠(fk), 허용 값(enum), 칸 설명(cols)
- 적지 않은 자료 묶음은 점검 도구가 "규칙표에 없음"으로 알려 줍니다.
- 자료는 반드시 `H.store`(저장 장치)를 통해서만 만들고 바꿉니다.
  - 새 자료: `S.add`(번호 겹침을 자동으로 막음)
  - 고친 뒤 저장: `S.save`
- 처방 상태는 반드시 `H.flow.advance`로 바꿉니다. 그래야 단계 이력(`hist`)과 활동 기록이 남습니다.
- 사람을 가리킬 때는 이름이 아니라 번호로 연결합니다(`patientId`, `pid`, `encId`, `orderId`).
  - 이름은 보여 주기용으로만 함께 저장합니다.

## 2. 처방 흐름 규칙표
- 처방 흐름 규칙표는 `js/core/integrity.js`의 `ROUTES`에 있습니다.
- 처방 분류(MED·INJ·LAB·RAD·PATH·PROC·NUR·DIET·BLOOD·CONSULT·OP·CV·EN)마다 모든 단계에 담당 부서 화면이 있어야 합니다.
- 단계 정의는 `js/core/flow.js`의 `STEPS`에 있습니다.
  - 단계를 추가하면 ROUTES에도 담당 화면을 적습니다.
  - 그 화면에 실제로 처리 버튼을 만듭니다.
- 끝난 처방은 진료비 계산(`js/core/fee.js`)을 거쳐 원무 수납 → 심사·코딩 → 청구로 이어집니다.
  - 간호처방·식이·협진은 진료비에서 제외합니다.

## 3. 점검과 보호
- 프로그램 안 **실습 관리 › 데이터 점검** 화면에서 자료를 점검합니다.
- 점검하는 것:
  - 끊긴 연결
  - 빠진 필수 칸
  - 정해진 값이 아닌 상태
  - 단계와 결과가 맞지 않는 처방
  - 같은 침상에 두 환자, 한 환자의 중복 입원
  - 규칙표에서 빠진 단계
- 자동 고침은 자료를 지우지 않고 바로잡기만 합니다.
- 화면 아래 상태 줄에 점검 결과(정상 / 오류 n건)가 늘 보입니다.
- 저장할 때마다 다시 읽어서 제대로 저장됐는지 확인합니다.
  - 실패하면 화면에 경고하고, 상태 줄에 "저장 실패!"를 표시합니다.
- 예비 사본(`ssvh.v1.db.bak`):
  - 10분마다, 그리고 "처음 상태로"·"기록 가져오기" 직전에 만듭니다.
  - 저장 자료가 손상되면 열 때 자동으로 복구합니다.
- 자료 형식을 바꿀 때는 `store.js`의 `VERSION`을 올리고 `MIGRATE`에 옮기는 방법을 적습니다.
  - 기존 실습 기록은 절대 지우지 않습니다.
- 다른 창(탭)에서 저장하면 이 창 자료도 바로 바뀝니다. 그래서 오래된 자료로 덮어쓰지 않습니다.

## 4. DB 연결
- **데이터 점검 › DB 연결용** 탭에서 세 가지를 복사할 수 있습니다.
  - 테이블 생성문(SQL, PostgreSQL 기준)
  - 자료 규칙표(JSON)
  - 전체 자료(JSON)
- 묶음 이름 = 테이블 이름, 칸 이름 = 열 이름입니다.
- 규칙표에 없는 칸은 각 테이블의 `extra`(JSON) 열에 넣습니다.
- 저장 장치(`js/core/store.js`)의 `load`, `save`, `add`, `get`, `where`만 서버 API 호출로 바꾸면, 화면 코드는 그대로 DB에 붙습니다.

## 5. 고칠 때마다 하는 점검 (빠뜨리지 않기)
1. 새 파일은 `node --check`로 문법을 검사합니다.
2. 미리보기에서 **처음 상태로** 한 뒤 데이터 점검을 엽니다. 오류 0건이어야 합니다.
3. 바꾼 처방 흐름은 외래·입원·응급에서 끝 단계까지 진행합니다.
   - 진료비 계산에 빠진 처방이 없어야 합니다.
4. 휴대폰 폭(390px)에서 화면이 옆으로 넘치지 않아야 합니다.

## 6. 한글로 / 영어로 (화면 번역)
- 번역 장치는 `js/core/i18n.js`이고, 영어 사전은 `js/i18n/dict-en.js`(자동 생성)입니다.
  - 화면을 그린 뒤 글자를 영어로 바꿉니다.
  - 입력칸(input·textarea)과 `.no-tr` 표시가 붙은 곳은 바꾸지 않습니다.
- 사람 이름(환자·직원·로그인·의뢰 환자·고객)은 영어 화면에서도 한글 그대로 둡니다 (사용자 요청). 사전에도 이름을 영어로 적지 않습니다.
- **새 화면이나 새 문구를 추가하면 영어 사전도 함께 갱신합니다.**
  1. 미리보기에서 화면 글자를 모아 `tools/_work/ko-runtime.txt`(원문 목록)로 저장합니다.
     - 미리보기 서버의 `/__dump`(목록 받아 저장하기) 기능을 씁니다.
  2. `node tools/i18n-extract.js`로 알림 창·확인 창 문구를 더합니다.
  3. 새로 생긴 원문 줄을 번역해 `tools/i18n/en-*.txt`에 "번호<TAB>영어" 형식으로 적습니다.
     - 숫자 자리 `#`와 이름 자리 `@`의 개수는 원문과 같아야 합니다.
     - 낱말 단위 용어는 `tools/i18n/terms.txt`에 적습니다.
  4. `node tools/i18n-build.js`로 사전을 다시 만듭니다.
  5. 영어로 바꾼 뒤 모든 화면·탭을 열어 남은 한글이 0개인지 확인합니다.

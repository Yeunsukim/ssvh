# SSV 병원 전산 실습 — 데이터 연결·지속성 규칙

이 프로그램의 모든 자료는 병원 DB에 그대로 옮길 수 있게 **표(테이블) + 열쇠(FK)** 구조로 되어 있습니다.
새 화면을 만들거나 고칠 때는 아래 규칙을 반드시 지킵니다.

## 1. 자료 규칙표가 기준이다
- 자료 규칙표는 `js/core/integrity.js`의 `SCHEMA`에 있습니다.
- 자료 묶음 27개(patients, encounters, orders …)는 각각 DB 테이블 1개와 같습니다.
- 새 자료 묶음이나 다른 자료를 가리키는 새 칸(열쇠)을 만들면 **먼저 SCHEMA에 적습니다.**
  - 적을 것: 표 이름, 필수 칸, 열쇠(fk), 허용 값(enum), 칸 설명(cols)
- 적지 않은 자료 묶음은 점검 도구가 "규칙표에 없음"으로 알려 줍니다.
- 자료는 반드시 `H.store`(저장 장치)를 통해서만 만들고 바꿉니다.
  - 새 자료: `S.add`(번호 겹침을 자동으로 막음)
  - 고친 뒤 저장: `S.save`
- 처방 상태는 반드시 `H.flow.advance`로 바꿉니다. 그래야 단계 이력(`hist`)과 활동 기록이 남습니다.
- 사람을 가리킬 때는 이름이 아니라 번호로 연결합니다(`patientId`, `pid`, `encId`, `orderId`).
  - 이름은 보여 주기용으로만 함께 저장합니다.

## 2. 처방 흐름 규칙표
- 처방 흐름 규칙표는 `js/core/integrity.js`의 `ROUTES`에 있습니다.
- 처방 분류(MED·INJ·LAB·RAD·PATH·PROC·NUR·DIET·BLOOD·CONSULT·OP·CV·EN)마다 모든 단계에 담당 부서 화면이 있어야 합니다.
- 단계 정의는 `js/core/flow.js`의 `STEPS`에 있습니다.
  - 단계를 추가하면 ROUTES에도 담당 화면을 적습니다.
  - 그 화면에 실제로 처리 버튼을 만듭니다.
- 끝난 처방은 진료비 계산(`js/core/fee.js`)을 거쳐 원무 수납 → 심사·코딩 → 청구로 이어집니다.
  - 간호처방·식이·협진은 진료비에서 제외합니다.

## 3. 점검과 보호
- 프로그램 안 **실습 관리 › 데이터 점검** 화면에서 자료를 점검합니다.
- 점검하는 것:
  - 끊긴 연결
  - 빠진 필수 칸
  - 정해진 값이 아닌 상태
  - 단계와 결과가 맞지 않는 처방
  - 같은 침상에 두 환자, 한 환자의 중복 입원
  - 규칙표에서 빠진 단계
- 자동 고침은 자료를 지우지 않고 바로잡기만 합니다.
- 화면 아래 상태 줄에 점검 결과(정상 / 오류 n건)가 늘 보입니다.
- 저장할 때마다 다시 읽어서 제대로 저장됐는지 확인합니다.
  - 실패하면 화면에 경고하고, 상태 줄에 "저장 실패!"를 표시합니다.
- 예비 사본(`ssvh.v1.db.bak`):
  - 10분마다, 그리고 "처음 상태로"·"기록 가져오기" 직전에 만듭니다.
  - 저장 자료가 손상되면 열 때 자동으로 복구합니다.
- 자료 형식을 바꿀 때는 `store.js`의 `VERSION`을 올리고 `MIGRATE`에 옮기는 방법을 적습니다.
  - 기존 실습 기록은 절대 지우지 않습니다.
- 다른 창(탭)에서 저장하면 이 창 자료도 바로 바뀝니다. 그래서 오래된 자료로 덮어쓰지 않습니다.

## 4. DB 연결
- **데이터 점검 › DB 연결용** 탭에서 세 가지를 복사할 수 있습니다.
  - 테이블 생성문(SQL, PostgreSQL 기준)
  - 자료 규칙표(JSON)
  - 전체 자료(JSON)
- 묶음 이름 = 테이블 이름, 칸 이름 = 열 이름입니다.
- 규칙표에 없는 칸은 각 테이블의 `extra`(JSON) 열에 넣습니다.
- 저장 장치(`js/core/store.js`)의 `load`, `save`, `add`, `get`, `where`만 서버 API 호출로 바꾸면, 화면 코드는 그대로 DB에 붙습니다.

## 5. 고칠 때마다 하는 점검 (빠뜨리지 않기)
1. 새 파일은 `node --check`로 문법을 검사합니다.
2. 미리보기에서 **처음 상태로** 한 뒤 데이터 점검을 엽니다. 오류 0건이어야 합니다.
3. 바꾼 처방 흐름은 외래·입원·응급에서 끝 단계까지 진행합니다.
   - 진료비 계산에 빠진 처방이 없어야 합니다.
4. 휴대폰 폭(390px)에서 화면이 옆으로 넘치지 않아야 합니다.

## 6. 한글로 / 영어로 (화면 번역)
- 번역 장치는 `js/core/i18n.js`이고, 영어 사전은 `js/i18n/dict-en.js`(자동 생성)입니다.
  - 화면을 그린 뒤 글자를 영어로 바꿉니다.
  - 입력칸(input·textarea)과 `.no-tr` 표시가 붙은 곳은 바꾸지 않습니다.
- 사람 이름(환자·직원·로그인·의뢰 환자·고객)은 영어 화면에서도 한글 그대로 둡니다 (사용자 요청). 사전에도 이름을 영어로 적지 않습니다.
- **새 화면이나 새 문구를 추가하면 영어 사전도 함께 갱신합니다.**
  1. 미리보기에서 화면 글자를 모아 `tools/_work/ko-runtime.txt`(원문 목록)로 저장합니다.
     - 미리보기 서버의 `/__dump`(목록 받아 저장하기) 기능을 씁니다.
  2. `node tools/i18n-extract.js`로 알림 창·확인 창 문구를 더합니다.
  3. 새로 생긴 원문 줄을 번역해 `tools/i18n/en-*.txt`에 "번호<TAB>영어" 형식으로 적습니다.
     - 숫자 자리 `#`와 이름 자리 `@`의 개수는 원문과 같아야 합니다.
     - 낱말 단위 용어는 `tools/i18n/terms.txt`에 적습니다.
  4. `node tools/i18n-build.js`로 사전을 다시 만듭니다.
  5. 영어로 바꾼 뒤 모든 화면·탭을 열어 남은 한글이 0개인지 확인합니다.

## 7. 처방 항목(마스터)과 샘플 자료 늘리기
- 처방 항목은 `js/data/master.js`(기본 206개) + `js/data/master2.js`(확장, 합계 약 1,200개)입니다. 새 항목은 master2.js에 **[한글, 영어]를 함께** 적습니다. 영어는 `H.I18N_PAIRS`로 들어가 영어 화면 사전에 자동으로 합쳐집니다.
- 번호 규칙: 약 D02xx, 주사 J03xx, 검사 L11xx, 영상 R31xx, 병리 P41xx, 처치 C71xx, 간호 N51xx, 식이 F61xx, 혈액 B81xx, 협진 K91xx, 수술 O91xx, 심혈관 V81xx, 내시경 E82xx. 기존 화면이 직접 쓰는 번호(예: L1026, O9005, C7011)는 바꾸지 않습니다.
- 항목마다 꼭 있어야 하는 칸: 약·주사(ing·cls·dose·unit·route·freq·maxDay·price), 검사(tube·part·items·price), 영상(kind는 sim.js 그림 종류 중 하나·mod·price, 핵의학은 nm), 기능검사(func·room), 수술(dept·min·anes·price), 내시경(dept·min·prep·price). 가격이 없으면 청구되지 않습니다(점검 도구가 "주의"로 알림).
- 영상 정상 판독문은 항목의 `nf`(부위별 정상 소견)를 먼저 씁니다.
- 샘플 자료는 단계(phase)로 덧붙입니다: `seed9.js`(p9) = 지난 진료 이력 30가지 사례·가상 환자 약 70명. 이미 쓰던 브라우저에도 기록을 지우지 않고 덧붙습니다(store.js의 `p9`).
- 샘플 자료 규칙: 끝난 진료의 처방은 마지막 단계까지, 검사는 결과, 영상은 판독, 병리는 병리번호·진단, 약·주사는 도착 시각과 투약 기록, 끝난 진료는 영수증(bills)까지 만듭니다. 지난 진료의 약은 `done: true`(지금 쓰는 약 목록·중복 점검에서 빠짐). 외래·응급 주사는 투약 기록을 남겨 오늘 주사실 대기열에 뜨지 않게 합니다.
- 영어 문장은 **파일을 불러올 때** 등록합니다(단계 함수 안에서만 등록하면 이미 그 단계가 저장된 브라우저에서는 번역되지 않음). 저장 자료에는 한글만 넣습니다.
- 점검 규칙 추가(2026-11-09): 병리 판독완료에는 진단(result.dx)이 꼭 있어야 하고(오류), 병리 접수 뒤에는 병리번호(pathNo)가 있어야 합니다(주의, 자동 고침 가능).

## 8. 간호행정 3교대 근무표 (js/modules/p12-duty.js)
- 자료: `staff[].sched = { 'YYYY-MM-DD': 근무 코드 }`. 코드는 D(낮번)·E(초번)·N(밤번)·OFF(정규 휴무)와 휴무 사유 AL(연차)·EDU(교육, 근무 인정)·SL(병가)·FL(경조)·PL(공가)·HL(보건)·ML(출산·육아). 다른 값이 들어가면 자료 점검이 "주의"로 알립니다.
- 확정(게시) 기록: `recs` kind `duty` { ward, ym, status('확정'·'확정 후 수정 중'), warn(규칙 확인 건수) }. 작성·자동 짜기·확정은 활동 기록(audit) "근무표 작성"으로 남고, 교수자 점검표가 이것을 셉니다.
- 한 달 단위로 작성: 위쪽에서 병동과 달을 고르고, 휴가·교육 신청을 먼저 넣은 뒤 "한 달 자동 짜기"는 **빈칸만** 채웁니다. "근무 지우기"는 사유가 있는 칸을 남깁니다.
- 조회: 월 단위(한 달 전체 + 사람별 D·E·N·휴무·교육 합계 + 날짜별 근무조 인원), 주 단위(월요일 시작 7일, 근무 시간·근무조별 명단).
- 샘플(p10): 병동마다 간호사 12명, 지난달·이번 달 확정 근무표, 다음 달은 휴가·교육 신청만.
- 한 글자 낱말(요일·일·년)은 사전에 넣지 않고 화면에서 직접 언어별로 씁니다(사전에 넣으면 다른 화면의 같은 글자까지 바뀜).

## 9. 영어 화면 — 기록 내용까지 번역 (2026-11-10)
- 영어로 바꾸면 화면 글자뿐 아니라 저장된 기록(진단명·소견·검사 결과·판독·병리·의사/간호 기록·고객의 소리 등)과 입력칸에 미리 채워진 글(진단서 문구·예시 글)도 영어로 보입니다. **사람 이름과 주소만 한글 그대로**입니다.
- 번역 자료: `tools/i18n/pairs-*.txt` ("한글<TAB>영어", 숫자는 #, 이름은 @ — 개수가 같아야 함). `node tools/i18n-build.js`로 js/i18n/dict-en.js를 다시 만듭니다.
- 번역 장치(i18n.js): ① 사전에 통째로 있으면 그대로 ② 숫자·이름을 #·@로 바꾼 틀이 있으면 채워 넣기 ③ 짧은 글은 아는 낱말만 바꿔도 씀, 긴 글은 사전 조각만으로 한글이 하나도 안 남을 때만 씀 ④ 입력칸은 한 줄씩 번역해 끝까지 영어가 될 때만 바꾸고, 버튼을 누른 직후(예: 예시 글 채우기)에도 다시 번역.
- 학생이 직접 타이핑한 새 문장은 사전에 없으면 한글 그대로 남습니다(프로그램 안에 자동 번역기가 없음).
- 새 기록 문장·예시 글·자동 결과 문장을 코드에 넣으면 영어도 pairs 파일에 함께 적습니다. 점검 도구: `tools/crawl-en.js`(화면), `tools/i18n-gaps.js`(사전에 없는 기록 문장), `tools/i18n-gen.js`·`tools/i18n-gen2.js`(자동 생성 문장).
